========================================================================
LAN 구간 통신 방법 (MAC 주소 통신)
========================================================================

------------------------------------------------------------------------
1. 사설 IP와 NAT
------------------------------------------------------------------------

공인 IP 주소가 부족(고갈)해서 나온 대안
  -> 사설 IP + NAT

  사설 IP : LAN 구간 내부에서만 사용, 다른 LAN과 중복 가능
  공인 IP : WAN(인터넷) 구간에서 사용, 중복 불가
  NAT     : 사설 IP <-> 공인 IP 변환

사설 IP 대역
  10.0.0.0    ~ 10.255.255.255     (10.x.x.x)
  172.16.0.0  ~ 172.31.255.255     (172.16.x.x ~ 172.31.x.x)
  192.168.0.0 ~ 192.168.255.255    (192.168.x.x)


------------------------------------------------------------------------
2. LAN 구간에서 MAC 주소로 통신하는 이유
------------------------------------------------------------------------

LAN 1 : 192.168.10.1
LAN 2 : 192.168.10.1
LAN 3 : 192.168.10.1

-> 사설 IP는 LAN마다 중복될 수 있음
-> 공인 구간에서 ping 192.168.10.1 을 하면 어느 장비인지 알 수 없음
-> 그래서 LAN 구간 안에서는 IP 대신 MAC 주소를 이용해 통신


========================================================================
MAC 주소 알아오는 방법 (ARP)
========================================================================

MAC 주소는 어떻게 알아오나?
  -> ARP 라는 프로토콜을 사용

ARP (Address Resolution Protocol, 주소 해석 프로토콜)
  상대방 IP 주소 --> MAC 주소를 받아옴 --> MAC 주소로 통신

ICMP (Internet Control Message Protocol)
  ping 명령어가 사용하는 프로토콜, 통신이 되는지 확인하는 메시지

ping 실행 순서
  ping 입력 -> ICMP 생성 -> 상대 MAC 주소를 모르면 ARP 먼저 실행


========================================================================
허브 환경에서의 ARP 동작
========================================================================

  PC A (192.168.10.1) ---- [ Hub ] ---- PC C (192.168.10.3)
                              |
                         PC B (192.168.10.2)

PC A 에서 ping 192.168.10.3

1. PC A 가 ICMP 생성, C 의 MAC 주소를 몰라서 ARP Request 생성
     출발지 IP  : 192.168.10.1
     목적지 IP  : 192.168.10.3
     출발지 MAC : A
     목적지 MAC : FFFF.FFFF.FFFF (브로드캐스트)

2. 허브는 받은 포트를 제외한 모든 포트로 전달 (Flooding)

3. PC B : 목적지 IP 가 자기가 아니므로 폐기

4. PC C : ARP Request 를 받고 ARP Reply(응답) 생성
     출발지 IP  : 192.168.10.3
     목적지 IP  : 192.168.10.1
     출발지 MAC : C
     목적지 MAC : A

5. 허브는 응답도 모든 포트로 Flooding
   -> PC B 는 다시 폐기, PC A 가 C 의 MAC 주소를 알게 됨

* 허브는 MAC 주소를 학습하지 않으므로 항상 Flooding


========================================================================
스위치 환경에서의 ARP 동작
========================================================================

  PC A (192.168.10.1) ---- [ Switch ] ---- PC C (192.168.10.3)
                              |
                         PC B (192.168.10.2)

PC A 에서 ping 192.168.10.3

1. PC A 가 ICMP 생성, ARP Request 생성
     출발지 IP  : 192.168.10.1
     목적지 IP  : 192.168.10.3
     출발지 MAC : A
     목적지 MAC : FFFF.FFFF.FFFF (브로드캐스트)

2. 스위치가 ARP Request 수신

3. 스위치가 출발지 MAC 을 MAC 주소 테이블에 학습 (Learning)
     MAC A -> PC A 가 연결된 포트

4. 목적지가 브로드캐스트이므로 나머지 모든 포트로 Flooding

5. PC B : 목적지 IP 가 자기가 아니므로 폐기

6. PC C : ARP Request 를 받고 A 의 MAC 주소를 등록

7. PC C 가 ARP Reply(응답) 생성
     출발지 IP  : 192.168.10.3
     목적지 IP  : 192.168.10.1
     출발지 MAC : C
     목적지 MAC : A

8. 스위치가 출발지 MAC 을 학습
     MAC C -> PC C 가 연결된 포트

9. 목적지 MAC A 가 테이블에 있으므로 PC A 포트로만 전달 (Forwarding)
   -> PC B 에는 전달되지 않음

MAC 주소 테이블 결과
  MAC A  |  PC A 연결 포트
  MAC C  |  PC C 연결 포트


------------------------------------------------------------------------
허브 vs 스위치
------------------------------------------------------------------------

허브   : MAC 학습 X, 요청/응답 모두 Flooding
스위치 : MAC 학습 O, 브로드캐스트만 Flooding,
         테이블에 있는 MAC 은 해당 포트로만 Forwarding
